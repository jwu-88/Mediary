# Mediary Firestore Schema

This schema stores user-owned medication data in Firestore. Every document
lives beneath the authenticated user's document so one user's health data
cannot be mixed with another user's data.

## Document tree

```text
users/{uid}
├── medications/{medicationId}
├── schedules/{scheduleId}
├── doseLogs/{doseLogId}
├── savedMedications/{medicationId}
├── reports/{reportId}
└── scans/{scanId}
```

`uid` is the Firebase Authentication user ID. Firestore document IDs should be
generated by the client unless a stable external ID is required.

## `users/{uid}`

The user document is the ownership boundary and a lightweight account summary.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `email` | string | yes | Copy of the authenticated email for display only. |
| `displayName` | string | yes | User-editable name. |
| `bloodType` | string | yes | User-entered blood type. |
| `allergies` | array<string> | yes | User-entered allergy names. |
| `careTeam` | string | yes | User-entered care-team summary. |
| `createdAt` | timestamp | yes | Server timestamp on first profile creation. |
| `updatedAt` | timestamp | yes | Server timestamp on every profile update. |
| `timezone` | string | yes | IANA timezone, for example `America/New_York`. |
| `preferences` | map | yes | Appearance and notification preferences. |

Example:

```json
{
  "email": "person@example.com",
  "displayName": "Alex Morgan",
  "bloodType": "O+",
  "allergies": [],
  "careTeam": "",
  "createdAt": "server timestamp",
  "updatedAt": "server timestamp",
  "timezone": "America/New_York",
  "preferences": {
    "theme": "system",
    "accentColor": "blue",
    "doseNotifications": true,
    "followUpAlerts": true,
    "reminderSound": "Gentle Chime",
    "language": "English",
    "units": "Metric"
  }
}
```

## `users/{uid}/medications/{medicationId}`

One medication currently or previously tracked by the user. Keep this separate
from the public medication library so personal instructions and notes remain
private.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `name` | string | yes | Display name, for example `Metformin`. |
| `genericName` | string | yes | Generic name when known, or an empty string. |
| `strength` | string | yes | For example `500 mg`, or an empty string. |
| `form` | string | yes | Tablet, capsule, liquid, inhaler, and so on. |
| `route` | string | yes | Oral, topical, inhaled, etc. |
| `instructions` | string | yes | User-entered directions, or an empty string. |
| `prescriber` | string | yes | Optional clinician or practice name. |
| `pharmacy` | string | yes | Optional pharmacy name. |
| `notes` | string | yes | Private notes. |
| `active` | boolean | yes | Whether it appears in active medication lists. |
| `source` | string | yes | `manual`, `scanner`, or `library`. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |
| `archivedAt` | timestamp | no | Set instead of deleting historical medication data. |

## `users/{uid}/schedules/{scheduleId}`

A recurring or one-time instruction for taking a medication. A medication can
have multiple schedules.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `medicationId` | string | yes | ID in the user's `medications` collection. |
| `doseAmount` | number | yes | Positive amount. |
| `doseUnit` | string | yes | Tablet, capsule, mL, puff, or another unit. |
| `times` | array<string> | yes | Local `HH:mm` values, such as `08:00` and `20:00`. |
| `frequency` | string | yes | `daily`, `weekly`, `every8Hours`, `every12Hours`, `asNeeded`, or `once`. |
| `daysOfWeek` | array<number> | no | ISO weekdays `1`–`7`; required for weekly schedules. |
| `startDate` | string | yes | ISO calendar date `YYYY-MM-DD`. |
| `endDate` | string | no | ISO calendar date, inclusive. |
| `timezone` | string | yes | IANA timezone used when generating doses. |
| `instructions` | string | no | Food or timing instructions. |
| `active` | boolean | yes | Whether future doses should be generated. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |

## `users/{uid}/doseLogs/{doseLogId}`

An immutable-ish record of a scheduled dose and the user's response. The app
may update the status, but should not rewrite scheduled medication details
after the dose has occurred.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `medicationId` | string | yes | User medication ID. |
| `scheduleId` | string | yes | Schedule that generated this dose. |
| `scheduledFor` | timestamp | yes | Exact instant represented by the dose. |
| `localDate` | string | yes | User-local `YYYY-MM-DD`, useful for calendar queries. |
| `localTime` | string | yes | User-local `HH:mm`. |
| `status` | string | yes | `due`, `taken`, `missed`, `skipped`, `cancelled`, or `snoozed`. |
| `takenAt` | timestamp | no | Set when status becomes `taken`. |
| `snoozedUntil` | timestamp | conditional | Required when status is `snoozed`. |
| `notes` | string | no | Optional user note. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |

Use a deterministic ID such as `{scheduleId}_{scheduledForEpoch}` when creating
scheduled doses. This prevents duplicate doses when a device retries a sync.

## `users/{uid}/savedMedications/{medicationId}`

Stores the user's saved items from the medication library.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `savedAt` | timestamp | yes | Server timestamp. |
| `libraryVersion` | string | yes | Version of the public library item. |

The document ID is the public library medication ID, making save/unsave
idempotent.

## `users/{uid}/reports/{reportId}`

Cached weekly or custom-range summaries. Reports are derived data and can be
recomputed from `doseLogs`.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `periodStart` | string | yes | ISO calendar date. |
| `periodEnd` | string | yes | ISO calendar date, inclusive. |
| `doseCount` | number | yes | Scheduled doses in the period. |
| `takenCount` | number | yes | Doses marked taken. |
| `missedCount` | number | yes | Doses marked missed. |
| `skippedCount` | number | yes | Doses marked skipped. |
| `adherencePercent` | number | yes | `0`–`100`, rounded for display. |
| `generatedAt` | timestamp | yes | Server timestamp. |
| `sourceVersion` | string | yes | Version of the calculation logic. |

Use `{periodStart}_{periodEnd}` as the report ID for an idempotent weekly
report cache.

## `users/{uid}/scans/{scanId}`

Text-only metadata from a medication-label scan. The schema does not store
images or image URLs.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `status` | string | yes | `uploaded`, `processing`, `complete`, or `failed`. |
| `detectedMedicationName` | string | no | Text extracted by the scanner. |
| `extractedText` | string | no | OCR text from the label. |
| `confidence` | number | no | Extraction confidence from `0` to `1`. |
| `errorMessage` | string | no | Text-only failure details when processing fails. |
| `createdAt` | timestamp | yes | Server timestamp. |
| `updatedAt` | timestamp | yes | Server timestamp. |

## Recommended indexes

Create these composite indexes only when the corresponding queries are added:

- `doseLogs`: `localDate ASC`, `scheduledFor ASC`
- `doseLogs`: `medicationId ASC`, `scheduledFor DESC`
- `doseLogs`: `status ASC`, `scheduledFor DESC`
- `schedules`: `active ASC`, `startDate ASC`
- `reports`: `periodStart DESC`

## Data rules

- Every read and write must be scoped to the authenticated user's `uid`.
- Do not store passwords, access tokens, full medical records, or unredacted
  insurance information in Firestore.
- Do not add image, image-byte, image-URL, or file fields to these documents.
- Keep scan results as text and numeric confidence values only.
- Prefer archive fields over deleting medications or dose history.
- Treat scanner output as unverified until the user confirms it.
- Use Firestore server timestamps for audit fields.
- Store dates separately from instants: use ISO dates for calendar grouping and
  timestamps for events.
